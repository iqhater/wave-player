# Proposal

## Why

При загрузке длинных миксов (час и больше) анализ BPM и ключа декодирует весь файл в моно-буфер и передаёт его целиком в `stratum-dsp`. Для часового микса при 44.1 кГц это около 159 млн `f32` (~635 МБ) только входных сэмплов, не считая внутренних аллокаций DSP и пикового роста `Vec`. В результате анализ надолго занимает CPU и память (в отчёте пользователя — 83% RAM), а иногда приложение вылетает.

При этом у долгих миксов BPM меняется на протяжении записи, поэтому анализ всего часа не даёт более полезного результата, чем анализ начала. Пользователю достаточно увидеть BPM и ключ, определённые по первым минутам.

## What Changes

- BPM/key анализ выполняется только по первому окну трека (по умолчанию 10 минут), а не по всему файлу.
- Окно ограничивается и по времени, и по абсолютному числу кадров, чтобы файлы с высокой частотой дискретизации тоже не раздували буфер.
- `decode_mono` прекращает декодирование на границе окна и заранее выделяет буфер ограниченного размера.
- Треки короче окна анализируются как раньше, без изменений результата.
- `bpm_key_version` в кэше анализа повышается: сохранённые результаты, посчитанные по всему треку, один раз пересчитываются. Waveform-кэш и LUFS не затрагиваются.

**BREAKING:** нет. Меняется только внутренняя версия кэша анализа; SQLite-схема, `config.json` и пользовательские данные не меняются, миграция не требуется.

## Capabilities

### New Capabilities

- `player/track-analysis`: границы и ресурсные пределы фонового анализа BPM и музыкального ключа для длинных файлов.

### Modified Capabilities

Нет.

## Impact

**Backend:** `src/backend/analysis/service.rs` — ограничение окна декодирования и предвыделение буфера; `src/backend/analysis/bpm_key.rs` — версия результата анализа; unit-тесты в `service.rs`.

**Данные:** JSON-кэш анализа (`analysis/*.json`) получает новую `bpm_key_version`; старые записи `bpm_key` пересчитываются один раз. Формат waveform-кэша, SQLite и `config.json` не меняются.

**Зависимости:** новые не добавляются.

**Тесты:** Rust unit-тесты для границы окна и кэша; manual smoke на длинном миксе. E2E не добавляются.

## Non-goals

- Настройка размера окна в UI или `config.json`: используется фиксированное значение.
- Анализ BPM/ключа по всему миксу, по нескольким окнам или по выбранному loop-региону.
- Индикация в UI того, что BPM/ключ определены по первым 10 минутам.
- Изменение waveform-анализа, LUFS, ручного BPM и поведения beat grid на коротких треках.
- Оптимизация самого `stratum-dsp` или замена DSP-библиотеки.

## Assumptions

- Первых 10 минут достаточно для устойчивой оценки BPM и ключа трека с постоянным темпом; для микса это репрезентативное начало.
- Beat grid в UI берёт фазу из первого бита и достраивает равномерную сетку на всю длительность, поэтому частичный список битов не ломает отрисовку сетки за пределами окна анализа.
- Внутренние аллокации `stratum-dsp` пропорциональны длине входного буфера, поэтому ограничение входа ограничивает и пиковую память.
