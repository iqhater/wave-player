# Spec Delta

## Purpose

Описывает, в каких пределах фоновый анализ BPM и музыкального ключа обрабатывает аудио, чтобы длинные миксы не расходовали неограниченную память и не приводили к вылетам приложения.

## ADDED Requirements

### Requirement: Анализ BPM и ключа ограничен первыми 10 минутами

Для треков длиннее 10 минут система MUST выполнять анализ BPM и музыкального ключа только по первым 10 минутам аудио. BPM, ключ и beat grid MUST определяться по проанализированному окну и публиковаться так же, как раньше.

**Verification:** unit-тест расчёта границы окна; manual smoke на часовом миксе с наблюдением за памятью процесса.

#### Scenario: Часовой микс

- **WHEN** загружается трек длительностью 60 минут
- **THEN** BPM и ключ определяются по первым 10 минутам, остаток файла не декодируется для этого анализа, а плеер остаётся отзывчивым

### Requirement: Окно анализа ограничено числом кадров

Для файлов с высокой частотой дискретизации система MUST дополнительно ограничивать окно анализа сверху по числу кадров, чтобы объём входного буфера не рос пропорционально частоте дискретизации без предела. Для 44.1 и 48 кГц MUST быть доступен полный 10-минутный отрезок.

**Verification:** unit-тест расчёта границы окна для 44.1, 48, 96 и 192 кГц; manual smoke с наблюдением за памятью процесса.

#### Scenario: Пиковая память ограничена

- **WHEN** анализируется часовой микс при 44.1 кГц
- **THEN** входной буфер анализа не превышает объёма 10 минут моно-аудио, и приложение не завершается из-за нехватки памяти

#### Scenario: Высокая частота дискретизации

- **WHEN** анализируется длинный файл с частотой дискретизации выше 48 кГц
- **THEN** число кадров анализа ограничено сверху, и объём буфера не растёт пропорционально частоте дискретизации без предела

### Requirement: Короткие треки анализируются полностью

Для треков длительностью 10 минут и меньше система MUST анализировать весь файл, как и до изменения. BPM, ключ и beat grid для таких треков MUST оставаться такими же, как при полном анализе.

**Verification:** unit-тест границы окна для длительности меньше лимита и ровно равной лимиту; integration-тест загрузки кэша и повторного анализа.

#### Scenario: Трек короче лимита

- **WHEN** загружается трек длительностью 3 минуты
- **THEN** анализируется весь трек, и результат совпадает с полным анализом

#### Scenario: Трек ровно 10 минут

- **WHEN** загружается трек длительностью ровно 10 минут
- **THEN** анализируется весь трек без усечения последнего кадра

### Requirement: Устаревший результат полного анализа пересчитывается один раз

Сохранённый результат BPM/ключа, посчитанный до введения окна, MUST быть признан устаревшим и пересчитан при следующей загрузке трека. Сохранённые waveform-данные и LUFS MUST быть переиспользованы. SQLite-схема, `config.json` и пользовательские настройки MUST NOT изменяться, миграция MUST NOT требоваться.

**Verification:** unit-тест `parse_cache` с версией результата предыдущего формата; integration-тест загрузки кэша с сохранёнными waveform и loudness.

#### Scenario: Загрузка старого кэша анализа

- **WHEN** для часового трека есть кэш с BPM/ключом, посчитанным по всему файлу
- **THEN** BPM и ключ пересчитываются по окну, а waveform и LUFS берутся из кэша без повторного расчёта

#### Scenario: Актуальный кэш

- **WHEN** для трека уже есть результат анализа по окну
- **THEN** повторный анализ BPM/ключа не запускается

### Requirement: Beat grid остаётся применимым ко всей длительности

Для трека длиннее окна анализа beat grid содержит биты только внутри окна. Система MUST продолжать отображать равномерную сетку на всей длительности, используя фазу первого найденного бита, и MUST сохранять snapping по сетке за пределами окна. Пустых участков сетки или waveform быть не должно.

**Verification:** существующие Node-тесты `tests/beat_grid.test.cjs` для фазы и snapping; manual smoke с прокруткой часового микса за отметку 10 минут.

#### Scenario: Прокрутка за пределы окна анализа

- **WHEN** пользователь открывает часовой микс и прокручивает волну за 10-минутную отметку
- **THEN** линии beat grid продолжают рисоваться равномерно по всей длительности

#### Scenario: Snapping за пределами окна

- **WHEN** включён snapping и пользователь ставит loop-маркер после 10-й минуты
- **THEN** маркер привязывается к линии сетки, построенной от фазы первого бита

### Requirement: Анализ длинного трека не блокирует воспроизведение

Ограничение окна MUST NOT менять поведение воспроизведения, seek, loop-региона и органов управления. Анализ MUST по-прежнему выполняться в фоне, а его результаты MUST обновлять только BPM, ключ и beat grid.

**Verification:** manual smoke во время анализа часового микса; существующие требования `player/waveform-loop` о фоновом анализе остаются в силе.

#### Scenario: Воспроизведение во время анализа

- **WHEN** часовой микс играет, а анализ BPM/ключа ещё выполняется
- **THEN** воспроизведение, seek и loop-регион работают без задержек, характерных для синхронного анализа

#### Scenario: Завершение анализа

- **WHEN** анализ окна завершается
- **THEN** обновляются только отображение BPM, ключа и beat grid, а состояние плеера не сбрасывается
