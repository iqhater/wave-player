# Design

## Context

`PlayerControls` скрывается на маршрутах `TermsOfService`, `PrivacyPolicy`, `Changelog` и `AppInfo` (`hide_controls` в `RootLayout`), поэтому при переходе на App Info панель управления размонтируется. Компонент `LUFS` в `src/gui/components/player_controls.rs` держит значение в локальном `use_signal` и получает его только из `PlayerEvent::LoudnessMeasured`. Это событие приходит из анализа один раз (и повторяется только при повторном анализе/запуске трека), broadcast-канал не хранит историю, поэтому после remount компонент остаётся с `None`.

`RootLayout` уже хранит в `PlaybackUIState` состояние, переживающее смену экранов (`bpm`, `key_name`, `key_numerical`, `beat_grid`, `metadata`), и обрабатывает события анализа в общем слушателе. `LoudnessMeasured` там сейчас не обрабатывается.

## Goals / Non-Goals

**Goals:**

- Сделать `LUFS-I` частью сессионного состояния уровня layout.
- Сохранить текущую валидацию значения (`finite`, `-60.0..=0.0`).
- Сбрасывать значение при смене трека и очистке анализа.
- Не менять хранилища, протокол событий и поведение анализа.

**Non-Goals:**

- Мгновенная и кратковременная громкость, LUFS-метры.
- Сохранение значения между перезапусками.
- Изменение кэша анализа или повторный запрос анализа при remount.

## Decisions

### D1. Значение в `PlaybackUIState`

Добавить в `PlaybackUIState` (`src/gui/layout.rs`) поле `integrated_lufs: Signal<Option<f32>>`, инициализировать `None` в `RootLayout` и передать в контекст. `LUFS` читает это поле вместо локального сигнала.

**Почему:** `RootLayout` живёт всё время работы приложения и уже владеет состоянием, которое должно переживать навигацию. Это тот же паттерн, что применён для избранного (`FavoriteSelection` + `PlaybackUIState.metadata`).

**Альтернативы:**
- Оставить локальный сигнал и запрашивать повторный анализ при монтировании — отклонено: лишняя CPU-нагрузка и задержка, событие уже было получено.
- Хранить в `AppConfig` — отклонено: это сессионное состояние, а не пользовательская настройка; запись в `config.json` добавила бы миграцию без пользы.

### D2. Обработка события в общем слушателе `RootLayout`

В `use_future`, который обрабатывает `PlayerEvent`, добавить ветку `LoudnessMeasured { integrated_lufs, .. }`:

- `Started` и `AnalysisCleared` устанавливают `None`;
- `LoudnessMeasured` применяет значение только если оно `Some`, конечно и входит в `-60.0..=0.0`, иначе оставляет предыдущее значение.

**Почему:** слушатель `RootLayout` существует всё время жизни UI, поэтому событие не теряется при remount панели управления. Мобильный и десктопный индикаторы читают один и тот же сигнал.

### D3. Чистая логика для тестов

Вынести в небольшую чистую функцию правило «какое значение показывать после события»:

```rust
fn accepted_integrated_lufs(current: Option<f32>, event: Option<f32>) -> Option<f32>
```

Функция возвращает `event`, если он валиден, иначе `current`. Это позволяет покрыть unit-тестами `None`, `NaN`, `±∞`, границы `-60.0`/`0.0` и значения вне диапазона без WebView. Компонент `LUFS` только форматирует значение (`{value:.1} LUFS-I`) и показывает «— LUFS-I» для `None`.

### D4. Без изменений в хранилищах

Поле не добавляется в `config.json`, SQLite и кэш анализа. `LoudnessMeasured` уже приходит из `analysis/service.rs` (в том числе из кэша), менять его формат не нужно. Миграции отсутствуют.

## Risks / Trade-offs

- **Потеря события, если `RootLayout` не смонтирован** → в текущей архитектуре `RootLayout` монтируется на всё время жизни UI, поэтому риск отсутствует. Значение сбрасывается только при старте нового трека и очистке анализа.
- **Событие с невалидным значением может «застрять» на предыдущем треке** → `Started` очищает значение раньше, чем приходит измерение, поэтому предыдущий трек не отображается. Для трека без измерения остаётся «—».
- **Дублирующиеся события** → идемпотентны: повторное валидное значение просто записывается ещё раз, ререндер произойдёт только при изменении сигнала.
- **Форматирование** → оставляем текущий формат `{value:.1}`, чтобы не менять внешний вид.

## Migration Plan

Не требуется. Изменение затрагивает только UI-состояние в памяти. Откат — revert коммита; данные пользователя не затрагиваются.

## Test Plan

- Unit: `accepted_integrated_lufs` — `None`, `NaN`, `+∞`, `-∞`, `-60.0`, `0.0`, `-80.0`, `5.0`, валидное значение сохраняется/заменяется.
- Unit: переходы состояния (старт трека → `None`, затем валидное событие → значение; очистка анализа → `None`).
- Integration: не требуется, границы хранилищ не меняются.
- Manual smoke: Home → App Info → Home при играющем треке; смена трека; трек без измерения; перезапуск приложения.
