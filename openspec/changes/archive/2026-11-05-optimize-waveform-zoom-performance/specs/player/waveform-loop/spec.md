# Spec Delta

## ADDED Requirements

### Requirement: Zoom and pan render from precomputed peaks

После получения пиков зум и панорама MUST отрисовываться из предрасчитанной пиковой пирамиды без декодирования аудио и без запроса в бэкенд на каждое изменение вьюпорта. Время отрисовки кадра MUST зависеть от ширины canvas, а не от длительности трека.

**Verification:** Node-тесты извлечённого JS проверяют выбор уровня, агрегацию и число операций отрисовки; manual smoke на часовом миксе.

#### Scenario: Rapid zoom near the end of a long track

- **WHEN** загружен часовой трек и пользователь быстро зумит участок в последних минутах
- **THEN** волна перерисовывается из уже загруженных пиков без декодирования и без новых запросов в бэкенд
- **AND** задержка не зависит от того, находится ли участок в начале или в конце трека

#### Scenario: Zoom back and forth

- **WHEN** пользователь многократно приближает и отдаляет один и тот же участок
- **THEN** каждый шаг зума перерисовывается из памяти без повторной загрузки данных

#### Scenario: Canvas width changes

- **WHEN** окно или сайдбар меняют ширину canvas
- **THEN** волна перерисовывается из тех же пиков и остаётся выровненной по времени
- **AND** дополнительные запросы к бэкенду не отправляются

### Requirement: Progressive fallback prevents empty viewport regions

Во время зума или панорамы каждый видимый пиксель MUST отрисовываться из лучшего доступного слоя: detail, mip или overview. При нехватке разрешения MUST использоваться более грубый уровень по участкам; canvas MUST NOT оставаться пустым там, где есть данные.

**Verification:** Node-тест частичного detail проверяет заполнение всех колонок; manual smoke быстрого Zoom Out.

#### Scenario: Fast zoom out after detail was loaded

- **WHEN** detail-окно загружено для приближённого участка и пользователь быстро отдаляет зум
- **THEN** участки слева и справа, не покрытые detail, заполняются более грубым уровнем пиков
- **AND** ни одна видимая колонка не остаётся пустой

#### Scenario: Partial detail window coverage

- **WHEN** локальное окно покрывает только часть текущего вьюпорта
- **THEN** покрытая часть рисуется из detail, а остальная — из mip-уровня
- **AND** граница между слоями не создаёт разрыва или двойного отображения

#### Scenario: Pyramid is still loading

- **WHEN** пиковая пирамида ещё не пришла, но overview уже доступен
- **THEN** весь вьюпорт рисуется из overview до поступления пирамиды
- **AND** пустые области не появляются

#### Scenario: Track has never been analyzed

- **WHEN** для трека ещё нет ни overview, ни пиков
- **THEN** отображается нейтральный placeholder на всю ширину canvas
- **AND** после завершения анализа placeholder заменяется волной

#### Scenario: Stale response after zoom out

- **WHEN** ответ на старый detail-запрос приходит после изменения вьюпорта
- **THEN** он не заменяет текущую отрисовку
- **AND** может быть сохранён в LRU окон для повторного использования

### Requirement: Multi-resolution peak pyramid is built once per track

При анализе MUST строиться finest min/max-уровень пиков с шагом около 3 мс при 44.1/48 кГц и ограничением числа бинов. Более грубые уровни MUST строиться из него без повторного декодирования. Выбор уровня MUST давать не более двух бинов на пиксель.

**Verification:** unit-тесты построения пирамиды и выбора уровня (Rust и Node); integration-тест загрузки пиков из кэша.

#### Scenario: One-hour mix

- **WHEN** проанализирован часовой трек
- **THEN** finest-уровень содержит min/max-пики с шагом около 128 кадров и укладывается в лимит бинов
- **AND** из него строятся все более грубые уровни без обращения к аудиофайлу

#### Scenario: Short track

- **WHEN** загружен трек длиной несколько минут
- **THEN** шаг finest-уровня остаётся не грубее примерно 3 мс
- **AND** число бинов и объём передачи остаются небольшими

#### Scenario: Extremely long track

- **WHEN** длительность трека превышает лимит finest-бинов
- **THEN** шаг пиков увеличивается до следующей степени двойки
- **AND** анализ завершается, а глубокий зум обслуживается локальными окнами

#### Scenario: Component remount

- **WHEN** пользователь уходит с экрана и возвращается к тому же треку
- **THEN** пиковая пирамида запрашивается заново и восстанавливается без повторного анализа файла

### Requirement: Extreme zoom uses bounded local windows

При разрешении выше finest-уровня MUST декодироваться только локальное окно вокруг видимой области (не более нескольких секунд), и оно MUST кэшироваться. Повторный зум или панорама внутри окна MUST NOT декодировать аудио; выравнивание MUST сохраняться.

**Verification:** unit/integration-тест окна с точным seek и маркером; Node-тест LRU; manual smoke максимального зума.

#### Scenario: Zooming beyond the finest peak level

- **WHEN** пользователь зумит глубже разрешения finest-уровня
- **THEN** декодируется только небольшое окно вокруг видимой области
- **AND** кадры до начала окна не декодируются в основном пути

#### Scenario: Pan inside the loaded window

- **WHEN** пользователь панорамирует внутри уже загруженного локального окна
- **THEN** новый запрос не отправляется и аудио не декодируется повторно

#### Scenario: Returning to a previously viewed window

- **WHEN** пользователь уходит из локального окна и возвращается к нему
- **THEN** ранее загруженные данные переиспользуются из кэша окон

#### Scenario: Format without accurate seek

- **WHEN** формат не поддерживает точный seek
- **THEN** локальное окно строится корректно через резервный последовательный путь
- **AND** позиция волны не смещается относительно overview

### Requirement: Viewport synchronization does not block zoom rendering

Canvas MUST обновляться немедленно на каждое изменение зума или панорамы. Синхронизация `zoom` и `view_center` с Dioxus MUST быть ограничена по частоте и MUST NOT вызывать декодирование, пересылку пиков или перерисовку дерева компонентов на каждый тик колеса.

**Verification:** Node-тест подтверждает, что путь колеса не отправляет команды загрузки; manual smoke с быстрым колесом; code review путей синхронизации.

#### Scenario: Rapid wheel input

- **WHEN** пользователь быстро вращает колесо мыши
- **THEN** canvas следует за зумом в каждом анимационном кадре
- **AND** сигналы вьюпорта обновляются реже, чем происходят события колеса, и не запускают загрузку данных

#### Scenario: Overlays catch up after the gesture

- **WHEN** изменение зума прекратилось
- **THEN** loop-оверлеи, beat grid и шкала времени приходят к итоговому вьюпорту с задержкой не более примерно 100 мс
- **AND** итоговое положение совпадает с положением волны

#### Scenario: Loop drag after zoom

- **WHEN** пользователь начинает перетаскивание loop-региона после зума
- **THEN** drag использует актуальный итоговый вьюпорт, а не промежуточное значение

### Requirement: Peak rendering stays aligned with the timeline

Позиция каждого столбика MUST соответствовать абсолютному времени трека независимо от источника данных: mip-уровня, локального окна или overview. Переход между уровнями MUST NOT вызывать горизонтальный скачок волны, курсора или beat grid.

**Verification:** Node-тесты с известными маркерами на разных уровнях; unit-тест окна, начинающегося не с нуля; manual smoke при переходе границы разрешения.

#### Scenario: Known marker near the end

- **WHEN** в последних секундах трека есть выраженный всплеск и пользователь зумит на него
- **THEN** всплеск отображается в той же временной позиции, что и на overview
- **AND** позиция не смещается при переходе между уровнями пиков

#### Scenario: Crossing the finest peak boundary

- **WHEN** пользователь плавно увеличивает зум и переходит с mip-уровня на локальное окно
- **THEN** волна не прыгает по горизонтали и не меняет масштаб
- **AND** курсор воспроизведения остаётся на том же времени

#### Scenario: Pan after a local window request

- **WHEN** локальное окно получено и пользователь панорамирует
- **THEN** новые столбики стыкуются с предыдущими без разрыва и двойного отображения

### Requirement: Waveform cache version 3 upgrades without losing user data

Waveform-кэш MUST хранить overview и finest-уровень пиков (версия 3). Кэши предыдущей версии MUST игнорироваться и пересоздаваться, повреждённый кэш MUST NOT блокировать анализ, воспроизведение или overview. `config.json`, SQLite и пользовательские данные MUST остаться неизменными.

**Verification:** integration-тесты round-trip, старой версии, повреждённого файла и ошибки записи; manual smoke после обновления.

#### Scenario: Update with an old cache

- **WHEN** приложение обновлено, а на диске остался waveform-кэш версии 2
- **THEN** старый файл игнорируется без ошибки
- **AND** трек анализируется повторно и получает кэш версии 3

#### Scenario: Cache round-trip

- **WHEN** анализ завершён и waveform-кэш сохранён
- **THEN** overview и пиковая пирамида загружаются без потери точности отображения
- **AND** после перезапуска зум работает без полного анализа

#### Scenario: Corrupted cache

- **WHEN** файл кэша обрезан или содержит некорректные значения
- **THEN** ошибка логируется, файл игнорируется
- **AND** трек анализируется заново, а воспроизведение и интерфейс не блокируются

#### Scenario: Cache cannot be written

- **WHEN** сохранение waveform-кэша завершается ошибкой
- **THEN** анализ и воспроизведение продолжаются
- **AND** пиковая пирамида остаётся доступной в памяти до смены трека или перезапуска
