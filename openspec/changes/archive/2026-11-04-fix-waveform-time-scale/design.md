# Design

## Root cause

В `src/gui/components/waveform.rs` разметка `Waveform` устроена так:

```
div.w-full                              // общий столбец (стр. 218)
├── div.flex.h-28.gap-2                 // (стр. 245)
│   ├── div.relative.flex.h-28.w-full   // waveform canvas, grid, курсоры, loop (стр. 247)
│   └── VolumeMeter                     // корень: w-14 shrink-0, hidden sm:flex
└── div.relative.mt-1.h-6.w-full        // шкала времени (стр. 448)
```

Шкала времени — сосед flex-строки, а не колонки с canvas. Её ширина равна ширине всей строки: `canvas + gap (0.5rem) + VolumeMeter (3.5rem)`. Проценты меток (`left: {pct}%`) считаются от этой общей ширины, тогда как waveform, курсор воспроизведения, beat grid и loop-регион позиционируются от ширины waveform-контейнера. На широком окне это даёт линейное расхождение примерно в 8–10%: для трека 7:09 метка `07:00` (97.9% шкалы) попадает за правый край canvas, который заканчивается на ~93.5% общей строки, — ровно то, что видно на скриншоте.

Первая мысль — выровнять подпись крайней левой метки по левому краю, а крайней правой — по правому. Вариант отклонён: подпись перестаёт быть центрированной относительно тика и налезает на соседнюю метку (первая и последняя подписи сливаются со следующими). Поэтому подписи остаются центрированными (`transform: translateX(-50%)`), как и раньше.

Отдельная причина наложения — фиксированный шаг: на узком окне 30-секундные метки оказываются ближе ширины подписи. Поэтому число меток дополнительно ограничивается шириной canvas.

## Решение

### 1. Шкала в одной колонке с canvas

Разметка перестраивается:

```
div.w-full
└── div.flex.w-full.min-w-0.items-start.gap-2
    ├── div.flex.min-w-0.flex-1.flex-col
    │   ├── div.relative.flex.h-28.w-full.min-w-0 ...   // canvas и оверлеи без изменений
    │   └── if has_track() && show_time_markers() { шкала }
    └── if has_track() { div.h-28.shrink-0.hidden.sm:block { VolumeMeter {} } }
```

- Колонка получает `flex-1 min-w-0`, поэтому её ширина равна ширине canvas при любом размере окна, сайдбара и брейкпоинта. Никакой JS-замер не нужен.
- `VolumeMeter` переносится в отдельного соседа с фиксированной высотой `h-28`, чтобы не растянуться на высоту колонки со шкалой и сохранить текущую геометрию индикатора.
- Обёртка метра скрывается вместе с ним на `sm`-брейкпоинте (`hidden sm:block`), поэтому скрытый метр не участвует в layout и не добавляет `gap`.
- Панель waveform сохраняет `h-28`, шкала — `mt-1 h-6`; суммарная высота блока не меняется.

### 2. Расчёт меток как чистая функция

Логика меток выносится из `rsx!` в функцию, принимающую длительность трека, видимый диапазон и ширину canvas:

```rust
struct TimeMark {
    pct: f32,
    label: String,
}

fn time_marks(
    duration_secs: f32,
    view_start_pct: f32,
    view_end_pct: f32,
    width_px: f32,
) -> Vec<TimeMark>
```

Правила:

- сохраняются текущие «круглые» интервалы, формат `MM:SS` и лимит 15 меток;
- число меток дополнительно ограничивается шириной: `floor(width_px / 60)` в диапазоне `2..=15`, поэтому при сужении окна шаг увеличивается, а подписи не перекрываются;
- секунды метки ограничиваются видимым диапазоном, процент — `[0, 100]`;
- метка, попадающая на самый правый край (`pct >= 99.5`), не добавляется, как и сейчас; при единственной метке используется `00:00`.

Ширина берётся из уже существующего `container_rect`, который обновляется при resize; дополнительных замеров или JS не требуется.

### 3. Разметка метки

Тик и подпись остаются единым блоком, центрированным в точке `left: {pct}%` через `transform: translateX(-50%)` — без изменений относительно текущего поведения. Контейнер шкалы остаётся `overflow-visible`, поэтому подпись у края может выступать за canvas в пределах окна, но не обрезается.

### 4. Плотность меток по ширине

`time_marks` принимает ширину canvas и вычисляет лимит меток:

```rust
const TIME_MARK_MIN_SPACING_PX: f32 = 40.0;
let max_marks = ((width_px / TIME_MARK_MIN_SPACING_PX).floor() as usize).clamp(2, 15);
```

Шаг выбирается из `NICE_TIME_STEPS` как первый, не меньший `range_secs / max_marks`. На широком окне лимит равен 15 и шаг 30 с для трека 7:09 сохраняется; на узком — меток становится меньше, а шаг остаётся «круглым».

## Затронутые компоненты и данные

- `src/gui/components/waveform.rs` — единственный изменяемый файл: разметка `Waveform`, вынос и тесты `time_marks`.
- `VolumeMeter`, `BeatGrid`, `LoopPlayer`, `WaveformBinsCanvas` не меняются.
- `UiConfig`, `config.json`, SQLite, кэши, команды и события не меняются; миграции не требуются.
- Состояние видимости шкалы (`ShowTimeMarkers`) остаётся в layout-сигнале и по-прежнему переживает навигацию и перезапуск; компонент его только читает.

## Рассмотренные альтернативы

- **Компенсация ширины через CSS (`calc(100% - 4rem)`, `mr-16`).** Отклонено: магическая константа дублирует ширину метра, ломается при её изменении и на брейкпоинте, где метр скрыт.
- **Перенос шкалы внутрь панели waveform как absolute-оверлея.** Отклонено: меняет высоту canvas или накладывает подписи на волну; выходит за рамки бага.
- **Вычисление позиций в пикселях по ширине canvas через JS.** Отклонено: проценты уже дают корректную координатную модель, а JS-замер добавляет гонки при resize и дублирование состояния.
- **Выравнивание крайних подписей по краям canvas.** Отклонено: смещает подпись относительно тика и приводит к наложению на соседние метки; достаточно согласовать ширину шкалы и canvas.

## Тест-план

| Требование | Проверка |
| --- | --- |
| Time scale matches the waveform canvas width | Manual smoke: трек 7:09, метка `07:00` внутри canvas; сравнение правых краёв шкалы и canvas при включённом/скрытом метре, после resize и сворачивания сайдбара. Геометрия WebView недоступна unit-тестам, e2e в проекте не используются. |
| Time marks stay within the visible range | Unit-тесты `time_marks`: все `pct` в `[0, 100]`, первая метка в `0%`, сохранение шага и формата, нулевая длительность, очень короткий трек, зум с ненулевым `view_start`; manual smoke при зуме и панорамировании. |
| Time marks do not overlap on narrow windows | Unit-тест: на ширине 300 px меток меньше, чем на 1000 px, минимальный зазор ≥ 40 px, а на ширине 620 px шаг для трека 7:09 остаётся 30 с; manual smoke при сужении окна. |
| Шкала выключена или трек не загружен | Manual smoke: настройка Timeline и запуск без трека. |

Регрессионный тест для самой ширины невозможен без UI-автоматизации: расхождение возникает только в реальной геометрии WebView. Поэтому unit-тесты фиксируют расчёт меток и их разрежение, а выравнивание ширины и отсутствие наложений подписей покрываются явным smoke-чеклистом.

## Риски

- Если `VolumeMeter` в будущем изменит ширину, шкала не пострадает: она привязана к колонке canvas, а не к метру.
- При ширине меньше 120 px даже две метки могут перекрываться; такие размеры вне практического диапазона использования.
